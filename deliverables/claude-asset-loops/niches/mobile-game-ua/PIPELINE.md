# Mobile game UA production

Static tier can run without ffmpeg. The hooks tier cannot.

1. Build a swipe file of three frames from `inbox/` only. The art director writes what the player does in each frame. If the verb is not visible, the frame is wrong.
2. Stills: one hook line, the verb in the picture, the game name on the end-state still only. Do not stamp "No.1 game" or a review score.
3. Squares are a reframed composition, not a squashed vertical. Re-place the type.
4. Hooks: second 0–2 is a fail state or a satisfying clear, already moving. Then the verb. Then the end card for at least the last 2 seconds with the call to action and the game name.
5. End card is also a still role so the client can run it as a freeze. Same words as the video's last frame.
6. Client-supplied footage is cut, not regenerated. Original staging is rendered and must not copy a specific existing game's UI chrome. Generic buttons are fine. Their HUD, if supplied, is used.
7. Video normalize per `TOOLSTACK.md`. Duration 14–20 seconds.
8. Roles: `vertical-still`, `square-still`, `vertical-video`, `endcard`.

Filename stills with the hook slug. A five-still tier that is five crops of one image fails the direction step before it ever reaches audit: the sheet has to name five compositions.
